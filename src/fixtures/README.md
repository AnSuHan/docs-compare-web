# 검수용 실문서 (픽스처)

파서가 실제 문서를 통과하는지 확인하는 자리다. `private/` 에 문서를 넣고 검수를 돌린다.

```bash
npm run inspect                     # private/ 아래 전부
npm run inspect -- 어떤파일.hwp     # 하나만
npm run inspect -- --json snapshots # NormalizedDoc 스냅샷까지 저장
```

`private/` 는 `.gitignore` 에 있다. 개인 문서를 넣어도 커밋되지 않는다.

## 무엇을 넣어야 하는가

기획서 §13.2 를 실무적으로 줄인 최소 세트다. 개수가 모자라도 시작은 된다.

| 종류 | 최소 개수 | 어디서 |
|---|---|---|
| 한글 공문서 `.hwp` | 5 | 정부24, 나라장터 공고문 |
| `.hwpx` | 3 | 같은 문서를 한/글에서 hwpx 로 저장 |
| 공문서 `.pdf` | 5 | 나라장터 공고문 (태그된 것/아닌 것 섞어서) |
| 스캔 `.pdf` | 1 | 인쇄 후 스캔한 것 아무거나 |
| `.docx` | 3 | 표·제목·목록이 있는 것 |
| 같은 원본을 다른 도구로 출력한 PDF 쌍 | 2쌍 | Word 출력 vs 한/글 출력 |

민감하지 않은 공개 문서면 된다.

## 결과를 어떻게 읽는가

`[ OK ]` 는 블록이 나왔고, 제어문자·U+FFFD 잔여가 0 이고, 신뢰도가 0.5 이상이라는 뜻이다.
`>` 로 시작하는 줄이 다음에 손댈 곳을 가리킨다 — 판정 기준은 `docs/NEXT.md` 의 P0-1 과 같다.

- HWP 성공률 **80% 미만이면 v1 에서 `.hwp` 를 뺀다** (기획서 §7.8-8)
- 제어문자 잔여가 0 이 아니면 `paraText.ts` 의 8 WCHAR 처리에 구멍이 있다
- PDF 트랙 A 적중률이 높으면 §6.5 기하 재조립 부담이 그만큼 준다
- 정상 한글 PDF 가 `GARBLED_TEXT` 로 잡히면 `hangulSanity.ts` 임계값이 과하다
